# 能力检测、版本兼容与自动降级

日期：2026-10-31。本文件是实施要求，不表示已经编译、安装或完成设备验证。适用于 US1–US9；US10 企业功能本次不接入，也不参与当前能力检查。

## 决策职责与版本范围

工程师根据官方资料、本机 SDK 和实际调用结果选择方案，记录依据后直接落实。芯片性能和系统版本影响能力，但同一版本设备的支持集可能不同；不用“旗舰支持、低端不支持”之类机型规则代替检测。

API 26 作为编译与增强体验基线。T001 优先评估 HarmonyOS 6.0 / API 20 及以上的兼容方案，逐项核对核心依赖的最低版本、低版本替代接口及模块装载限制，再锁定 `targetSdkVersion`、`compatibleSdkVersion` 和 ArkTS 编译模式。API 20 是待核定的工程候选，不是已支持承诺；若某个增强接口不能兼容，应先隔离或替换该接口，不能仅因它需要 API 26 就把整个应用的最低版本设为 26。确有核心依赖限制时记录具体原因与最终选择，无须用户决定 SDK 参数。

低于最终最低版本的系统不承诺可安装。已在最低版本范围内的设备，即使缺少某项增强能力，也必须能完成基础流程。只降低 `compatibleSdkVersion` 不能证明兼容。

## 检测与调用顺序

1. 先判断功能是否属于本次范围及产品隐私开关是否允许。关闭访问的入口先拒绝读数据，未实施功能不初始化、不展示可启用开关。
2. 按具体接口的起始版本判断：OpenHarmony 底座接口使用 `deviceInfo.sdkApiVersion`；HarmonyOS 特有接口按其声明核对 `deviceInfo.distributionOSApiVersion`。实施时以对应接口的 SDK 声明为准，不给所有接口套同一个版本号。
3. 检查该接口声明的 SysCap，使用 `canIUse`；接口提供专用支持检测时继续调用专用检测。设备类型只用于官方明确的适用范围，芯片型号只作排查参考。
4. 对需要权限、模型资源、服务初始化或平台开通的能力，分别检查实际条件。支持检测通过不代表已授权或模型已就绪；没有统一可用的模型检测接口时，按该 Kit 的初始化结果判断，不虚构通用接口。
5. 进入适配器后调用增强能力；不支持、初始化失败、资源不足或业务调用失败时保留草稿与照片，停止该次增强处理，回到表中基础方案。不能崩溃、卡住保存或静默改用云端。

版本保护必须覆盖组件创建和初始化。对最低版本上可能不可装载的模块，按 SDK 与编译模式支持的方式隔离装载；不能只在点击回调里加判断，却在页面启动时已经调用高版本接口。

## 状态与重新检测

适配层区分可用、版本不足、设备不支持、未授权、用户关闭、资源未就绪、暂时失败，以及实际接入所需的平台条件未满足；这些原因用于内部路由和诊断，不把枚举显示给用户。永久不支持时隐藏增强入口；权限或资源可恢复时，在使用位置说明原因并提供手工替代，用户主动操作后才请求授权或进入系统准备流程。

授权、设置或模型状态变化后，在返回应用或再次使用时重新检测，不能永久缓存首次失败。稳定的版本与设备支持结果可按系统版本缓存；系统升级后重新计算。暂时失败不误标为设备永久不支持，也不自动反复弹授权或下载提示。首次使用不因本轮能力探测自行申请网络权限或下载模型。

## 自动降级矩阵

| 能力 | 增强方案与检测重点 | 不可用时的完整基础方案 |
| --- | --- | --- |
| 悬浮底栏、材质与 HDS 组件 | API 起始版本、SysCap、材质专用检测和材质等级 | 使用基础 ArkUI 组件、纯色与边框；保留四个栏目、＋入口、统一面板和全部操作。组件不可装载时不创建它 |
| 光效、动画与触感 | 对应接口支持、系统减少动画和触感设置；材质不支持不代表其他能力也不可用 | 减少或关闭装饰效果，保留状态反馈、可读性、手势和操作区域；不由单一芯片档次关闭全部增强功能 |
| OCR、分割、多物体检测、图像分析与文档扫描 | 各 Kit 分别检测支持与资源就绪，按需初始化 | OCR 不可用则手填；分割不可用则保留原照片；多物体检测不可用则逐件记下；图像分析不可用仍可查看、缩放和保存照片；文档扫描不可用则拍照或选图保存 |
| 照片外观搜索 | 系统支持、索引就绪和用户开关 | 用名称、别名、位置、条码等文字搜索；索引准备不阻塞保存或普通搜索 |
| 离线语音、文本解析与朗读 | 麦克风授权、离线识别资源和识别服务；文本理解及朗读各自检测 | 保留已识别文字，转手工输入；可用文字先按应用句式解析，复杂解析不可用不丢原文，歧义由用户选择；朗读不可用仍完整显示结果文字 |
| 问问家当 | 由应用查询服务产生数量、位置、日期和借还事实，不依赖生成模型 | 始终显示查询结果与依据；自然语言无法确定目标时提供候选或转普通搜索，不编造答案 |
| 扫码、NFC 与碰一碰 | 分别检查扫码方式、相机授权、NFC 状态及分享能力 | 自定义扫码不可用时使用可用的系统扫码；无扫码能力则手填条码或在应用内选位置；无 NFC 则用二维码或位置页；无碰一碰则用普通系统分享 |
| 图标切换、卡片与端 A2A | 各自的版本、组件支持、授权及确需的平台条件 | 图标保留系统实际选择并继续切换应用内形象；卡片或 A2A 不可用仍能在应用内搜索、操作与查询，不能留下无效按钮 |
| 代理提醒 | 通知授权、实际配额、平台条件和发布结果 | 应用内待办与角标完整；可调度时按一次提醒、同日合并安排，不保证无通知权限仍能发通知 |
| 系统备份、跨设备、联系人和日历 | 对应设备/服务、系统授权与实际调用结果 | 便携备份和本机数据管理不受阻；跨设备不支持则留在本机继续草稿；联系人不可用则手填姓名；日历不可用则保留应用内归还日期 |

所有基础方案共用数量、查询和写入服务，不能为了降级另建一套数据规则。降级发生在当前面板或页面，保留用户输入、所在栏目和操作进度。

## 验证与结果记录

T015、T104 和 T122 实现共用判断；T001 锁定版本；T111 与 T144 记录兼容验收。每项至少覆盖“支持”“最低版本内但不支持”“权限拒绝/撤销”“资源未就绪/暂时失败”“恢复可用”。适用时验证系统升级、减少动画及深浅色。

纯规则测试可通过能力快照模拟分支。真实低版本系统仍需验证冷启动、页面创建、模块装载和核心流程；在新手机上关闭权限不能替代低版本测试，也不能证明硬件不支持时可运行。仅有 Mate 80 Pro Max 时记录该设备实际系统与结果，其他系统/设备标为未验证，继续完成适配，不把设备不足转成开发前的全局门槛。

验收按“增强路径通过”“降级路径通过”“待平台开通”“未验证”分别记录。隐藏未实现功能不等于完成实现；本次非企业功能不能因测试设备不支持而自行删掉支持设备上的实现。

## 官方依据与证据边界

- [API 版本与多设备兼容适配](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-ability-167)：版本保护与设备能力检查需结合，编译目标和最低运行版本分别配置。本轮 DeepSeek 搜索返回官方正文摘要；抓取该页仅得到站点外壳，未据此声称读取了完整正文。本机 API 26 的 `@ohos.deviceInfo.d.ts` 也声明了两个版本字段。
- [SysCap 与 canIUse](https://developer.huawei.com/consumer/cn/doc/doccenter-references/api/js-apis-syscap?docScope=all#caniuse)：系统能力集随设备不同，`canIUse` 查询的是对应系统能力，不是全部资源和授权状态。
- [On-Device Q&A Model](https://developer.huawei.com/consumer/en/doc/HarmonyOS-Guides/dataaugmentation-localchatmodel)：本轮抓取正文仍明确 localChatModel 仅企业开发者、PC/2in1，且有模型准备要求。该限制只针对这一接口，不能推广为所有手机都没有端侧 AI；它也不因芯片更强而消失。US10 按用户决定继续后置，本轮没有申请或接入。
