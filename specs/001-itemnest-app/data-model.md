# Data Model: 本地事实、约束与生命周期

输入依据：`docs/data.md`。以下根据需求定义业务字段；新增字段和本机辅助表均明确标注为设计选择，尚未实施。数据结构版本从 1 开始，后续逐级迁移。

## 实体与存储职责

| 表/存储 | 字段与关系 | 约束 |
| --- | --- | --- |
| `item` | 需求文档全部字段：id、name、name_pinyin、category_id、is_consumable、unit、notes、barcode、reminder_days、restock_mode、restock_threshold、cover_photo_id、last_activity_at、last_viewed_at、deleted_at、version | 名称 1 至 80 字，备注不超过 500 字，条码不超过 256 字符，提醒 0 至 365 天；单位非空；份可以为零个 |
| `item_alias` | item_id、alias、alias_pinyin | 每件最多 10 个；每个 1 至 20 字；同物品不重复 |
| `portion` | id、item_id、place_id、quantity、expiry_date、snoozed_until、expiry_ack、version | 数量为百分之一整数；同物品/位置/到期日唯一，空值视为相等 |
| `place` | id、parent_id、name、path、path_pinyin、sort_order、photo_id、last_used_at | 每级名称 1 至 40 字；最多 6 级，完整路径不超过 200 字；同级忽略大小写和首尾空白不重复；不能形成环 |
| `place_label` | token、place_id、name、kind | token 为随机 UUID；名称不超过 40 字；QR/NFC 只用于显示 |
| `category` | id、name、is_preset、consumable_default、archived、sort_order | 名称 1 至 40 字，全局唯一；预设分类可停用不可删除 |
| `photo` | id、item_id、kind、source、file、thumb、cutout、width、height、bytes、sort_order、indexed | 每件最多 9 张；JPEG 原图长边不超过 2048 像素、单张不超过 10 MiB；缩略图长边 512 像素；抠图 PNG |
| `person` | id、name、contact_key、last_lent_at | 名称 1 至 80 字，忽略大小写和首尾空白唯一；不获取联系人全量数据 |
| `loan` | id、item_id、portion_id、person_id、quantity、lent_at、due_date、note、voided_at、version | 一笔一个来源份；借出数量大于 0，备注不超过 200 字；未还不得小于零 |
| `loan_return` | id、loan_id、quantity、returned_at、note、voided_at | 数量大于 0、不超过未还；新增 `version` 供纠正及撤销核对，备注建议同借出不超过 200 字 |
| `stock_event` | 需求文档全部字段与 receipt、voided_at | 类型 CREATE、STOCK_ADD、CONSUME、DISCARD、MOVE、ADJUST、DELETE、RESTORE；保存历史显示快照，不能级联删除已完成动态 |
| `reminder_plan` | date、fire_at、system_reminder_id、content_hash、status、error | 每个提醒日一条；SCHEDULED/FAILED/FIRED 是内部状态，不原样显示 |
| `search_history` | id、query、created_at | 最近 20 条，相同内容只保留最新 |
| `backup_snapshot` | id、kind、file、bytes、item_count、photo_count、created_at | AUTO 保留 3 份，SAFETY 保留 1 份；不导出运行记录 |
| `command_log`（新增，本机辅助） | operation_id、kind、target_ids、committed_at、receipt、undo_state | operation_id 唯一；用于卡片重复投递、同次确认和撤销；不导出到便携备份 |
| `reminder_delivery`（新增，本机辅助） | event_key、reminder_date、content_version、published_at、delivered_at | 同一提醒事件仅通知一次，同日事件合并；无系统回调时不能把“已到计划时刻”伪称为已送达 |
| `nest_settings` | 原偏好表全部键值 | 保留原默认值供兼容；未实施企业扩展的有效状态始终为未启用，不显示可启用开关，不以偏好触发读取/共享/注册；系统授权与平台资格不属于偏好，不可通过恢复配置伪造 |
| 会话偏好（新增） | recent_units、browse_filters、shopping_session、capture_sessions、selected_character | 保存需求文档要求但未列键的最近单位、筛选、购物勾选、被打断草稿和形象；非业务事实、不导出到便携包 |

全部业务主键使用 UUID，时间点为毫秒时间戳，日期为本地日历日 `YYYY-MM-DD`。通用审计字段遵循需求文档；纯关联或辅助表按实际需要保留创建/更新时间，不用审计字段充当版本。

## DM-01：数量与零份

- 显示数量 = 内部整数 / 100；合法输入为 0 到 1,000,000，最多两位小数。用掉、补货、借出、归还、移动必须大于 0。
- 一笔未还 = 借出数量 − 未撤销归还之和；一份在手 = 份数量 − 此份未还之和；共有 = 所有份数量之和。
- 必须验证真实结果不小于零，不能用 `max(0, value)` 掩盖错误。更正数量保存为用户输入在手 + 未还。
- 设计选择：份数量与物品聚合共有均不超过 1,000,000（内部 100,000,000），合并、补货和更正同时校验，避免输入合法但聚合越界；用户若希望只限制单次输入，应先更新此约定。
- 普通物品默认数量 1、单位“个”；位置可空。零份物品保留 item，能够补货，位置显示“未放位置”或按页面呈现最后存放线索，不捏造当前库存。
- 自动用掉 1 先从在手大于 0 的份中确定最早一份，按到期日升序、无日期在后、创建时间和 ID 稳定决胜。该份在手至少为 1 才直接执行；不足 1 时展示“用掉…”让用户选择合法数量；不静默跳过该份或跨份扣减。这一边界细化见建议 S-04。

## DM-02：空值唯一与位置规范化

保存份之前，在同一事务内按 `(item_id, 归一化 place_id, 归一化 expiry_date)` 查找或合并。数据库层必须同时保证唯一：优先验证表达式唯一索引的支持；不支持时增加非空内部 key 列并用稳定哨兵表达空值，哨兵不能和 UUID/合法日期混淆。不得只建普通含 NULL 的唯一索引就认为符合 R4。

分类、借用人和同级位置使用独立规范化名称键；保留用户显示文字。位置改名、移动、递归合并在事务内先计算最终树，校验深度、完整路径、同名和自环，再一次更新路径和拼音。`place.path` 是缓存，ID 才是引用。

## DM-03：份合并、清零与历史借还

合并来源份 A 到目标份 B 时，在同一事务里：

1. 校验移动量不超过 A 的在手；只移动在手时，A 若有未还不能被整条移走。
2. 更新 A/B 数量；将确实发生整份合并的历史 `loan.portion_id` 重指到存活份，递增受影响借出的版本。
3. 历史显示不依赖被删除份的当前位置：借出/归还与动态保存当时的物品名、单位、来源位置路径快照。
4. 记录 A/B、被重指借出和相关版本到同一回执。后续有归还、纠正或数量改动时，旧回执必须拒绝撤销。

R5 清理零份时不级联删掉历史借还。设计选择：零份退出当前份列表；若历史仍引用，则保留内部历史锚点（如逻辑归档标记），直到历史可合法清理。若用户日后撤销旧借还，需要校验当前来源/合并关系、恢复合法份并再次校验所有不变量。该内部锚点不显示成额外库存，也不参与待办。物品永久删除才统一删除关联历史。归档锚点不参与活动份唯一键；同一键再次补货时可在事务内重新激活锚点或建立新的活动份，但仍须保证活动份唯一并保留历史来源。

## DM-04：版本与命令回执

每次业务变动递增受影响 `item`、`portion`、`loan` 和新增的 `loan_return.version`。资料单字段编辑的回执仅恢复被改字段，但仍按物品版本保守拒绝后续改动，不能回写旧数量、位置或日期。

回执包含 operationId、命令类型、目标、前后值、前后版本、创建/归档/合并关系与关联借还 ID。操作失败不生成成功回执。同 operationId 的重复投递只返回原结果，不再扣减；不同点击使用不同 ID，防止把合法连续操作误去重。

借还的历史纠正不受五秒提示条时限限制，但必须按当前数据重新校验。撤销借出时，其归还一并撤销；恢复该撤销时，只恢复本次一起撤销的归还，不能把更早已撤销的归还复活。跨操作恢复依赖回执记录，不允许直接批量清空 `voided_at`。

## DM-05：日期、待办与提醒

- R7 的最早到期日基于有数量的份；R22 的到期待办基于在手大于零的份，两者不能混用。
- 到期日早于今天为已过期；今天至今天加 N 天（含两端）为快到期；归还日早于或等于今天且未还大于零为该还了。
- 角标只包含过期、快到期、该还了的条目数；一件物品多份可产生多条，不能都写成去重后的物品件数。
- 缺货按共有判断，借出仍会还回，不按在手判断。普通物品不进入购物清单。
- 稍后和不再提醒只抑制相应份；修改到期日清理旧抑制状态和提醒事件键。
- 本地时区、日期或提醒时刻变化触发对账；日历月加减按目标月末约束，不用固定 30 天代替一个月。
- 提醒窗口只安排可用额度内的未来日期。已发布/触发的同一事件保留去重事实，避免下次启动再次提醒，同日事项合并为一条通知，不在提前窗口内每天重复。
- 卡片记录源数据版本与计算日期；版本一致时同口径，后台延迟不是另算一套结果的理由。

## DM-06：照片、草稿和派生索引

采用 `files/photos/{generation}/` 保存原图、缩略图和抠图，数据库只存相对路径；`generation` 是对源路径约定的实现补充。普通录入写入当前代，恢复写入新代。临时导入置于独立暂存区，不作为正式照片暴露。

新增、删图、换封面和排序同时维护 `cover_photo_id` 与 `sort_order`，两者不能独立决定不同封面。主体分割失败用原图；外观索引是可重建派生数据，照片删除、隐私开关关闭、恢复与永久删除时对账。

草稿保存输入与照片暂存引用，不提前建立正式物品。外部入口打断时保留旧草稿和新入口候选两个会话，不能单键覆盖后丢失旧输入。启动清理只删除既无数据库引用、也无有效草稿/会话/恢复暂存引用的文件。

## DM-07：删除、备份与隐私状态

软删除 item 后排除列表、搜索、待办和外部实体；取消提醒并移除派生索引。30 天清理按实际删除时间判断，事务提交后再删文件；仍被其他对象引用的共享文件不能误删。

便携备份表白名单、文件校验和代际切换见 `contracts/backup.md`。不导出 `command_log`、`reminder_delivery`、提醒系统 ID、购物会话、草稿和授权。恢复后保留本机用户设置的隐私选择，系统实际授权重新检查，不把缺失的隐私键重置为更开放的默认值。

系统备份/换机使用华为官方能力，按需求实现系统包含路径与排除规则，无需额外的数据离机确认。便携备份单独定义文件格式与恢复流程。不得复制旧设备的提醒 ID、卡片实例 ID 或已生效授权。
