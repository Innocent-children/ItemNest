# UI 与导航契约：ItemTrace 核心闭环

本契约定义页面间可见行为与参数边界，不定义 ArkUI 代码或具体路由 API。所有路由名在实现前
必须同步写入页面清单；页面参数只能传递稳定标识和显式结果，不传递完整可变 Item 对象。

| 页面 | 进入方式 | 输入 | 输出/返回 | 必须覆盖的状态 |
|---|---|---|---|---|
| 首页 | 应用启动、返回首页 | 无 | 搜索、新增、打开摘要目标 | 加载、暂无物品、摘要为空、数据库错误。 |
| 物品列表 | 首页查看全部、搜索返回 | 可选 `ItemQuery` | 打开详情、开始新增 | 加载、结果为空、筛选为空、读失败。 |
| 搜索 | 首页搜索、列表搜索 | 初始查询可选 | 已确认的 `ItemQuery` 或取消 | 空关键字、无结果、清除条件。 |
| 物品详情 | 列表/首页摘要点击 | 必填 `itemId` | 编辑、删除后刷新结果、返回 | 加载、记录不存在、读失败、删除确认。 |
| 新增物品 | 首页或列表快速新增 | 无 | `created(itemId)` 或取消 | 草稿、字段错误、保存中、保存失败。 |
| 编辑物品 | 详情编辑 | 必填 `itemId` | `updated(itemId)` 或取消 | 草稿、记录不存在、字段错误、保存失败。 |
| 设置 | Phase 2 首页入口 | 无 | 已更新的偏好/提醒状态 | 当前偏好、权限未授予、系统能力不可用。 |

## 刷新与一致性规则

1. 新增、编辑或删除成功后，返回值只含操作类型和 `itemId`；来源页面重新从 Repository 读取数据。
2. 取消或失败时不得返回“成功”结果，来源页面保留原有列表/详情数据。
3. 详情页接收的 `itemId` 查询不到记录时，显示“物品不存在或已删除”，并允许返回列表。
4. 搜索条件由 `ItemQuery` 表达：名称部分匹配、一个位置路径、一个分类；位置与分类同时存在时取交集。
5. 首页的三个摘要只读取派生数据：最近添加、即将到期、数量为零待补货。点击摘要项目必须进入
   同一 `itemId` 的详情页。

## 可访问性与敏感信息规则

- 到期状态必须有可读文字；颜色只能作为补充。
- 位置路径在列表中优先于分类；长文本可截断但详情必须可完整查看。
- 删除确认必须明确说明第一阶段不可恢复。
- Phase 2 的服务卡片只传递摘要计数和快速新增意图，不在桌面暴露 Item 详情。
