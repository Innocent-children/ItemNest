# 用户交互修复计划

**日期**：2026-06-21
**状态**：已实施主要修复（底部导航结构性改造暂缓）
**范围**：当前 HarmonyOS ArkTS 原生页面、组件、路由与页面状态。不得引入后端、账号、云同步、广告、第三方统计或未经核验的新权限。

## 目标

本计划用于修复当前 ItemTrace 中影响用户信心和操作效率的交互问题。优先级按“是否阻断主流程、是否导致误操作、是否影响日常高频使用”排序。

完成后应满足：

- 首次无数据用户可以从空状态顺利新增物品。
- 用户在长表单中不会因误触返回丢失未保存内容。
- 返回上级页面时数据实时更新，但不出现明显整页闪烁。
- 搜索、新增、详情维护、批次和管理入口符合常见移动 App 操作预期。
- 所有修复均通过 `assembleHap` 构建验证；未完成自动化测试时必须给出手工验收步骤。

## 实施记录

- P0 已完成：空状态新增参数、物品/批次表单未保存确认、返回刷新非阻塞化。
- P1 已完成主要项：搜索输入和筛选即时刷新；物品表单分层；数量快捷加减/置零；提醒天数快捷选择；保存、删除、批次、借还、位置/分类操作统一 toast 或 inline 错误反馈。
- P1-01 已做低风险收敛：位置/分类管理入口从首页移入设置页。底部导航暂缓，因为当前工程仍基于 `router.pushUrl/back` 栈式页面，直接用底栏 push 主页面会加重“返回像网页历史”的问题；应在后续统一迁移到 `Navigation/NavPathStack` 或明确 tab 栈策略后再实现。
- P2 已完成：物品卡片增加进入详情提示与按压态；详情页增强管理入口改为更清晰的批次/借还入口；搜索无结果和批次空状态补充场景化动作。
- 验证：已运行 `git diff --check` 和 `assembleHap`，构建通过；剩余 ArkTS warning 为既有 RDB/DAO 抛错声明与 router deprecated 警告。

## P0：必须先修

### UX-P0-01：修复空状态新增入口参数

**问题**：`EmptyState` 只按 `actionRoute` 跳转，无法传 `{ mode: 'create' }`。首页和列表空状态点击“新增物品”可能打开表单后提示“页面参数错误”。

**涉及文件**：

- `entry/src/main/ets/components/EmptyState.ets`
- `entry/src/main/ets/pages/Index.ets`
- `entry/src/main/ets/pages/ItemListPage.ets`
- `entry/src/main/ets/pages/ItemFormPage.ets`

**修复方向**：

- 让 `EmptyState` 支持显式路由参数，或改成由页面传入明确动作。
- 首页“暂无物品”与列表“暂无物品”必须跳转 `RouteName.ITEM_FORM` 且传入 `{ mode: 'create' }`。
- 筛选无结果时的空状态只执行“清除条件”，不要误跳新增。

**验收**：

- 全新数据状态下：首页空状态点击新增，直接进入新增表单，不出现“页面参数错误”。
- 全部物品列表空状态点击新增，直接进入新增表单。
- 筛选无结果时点击清除后恢复完整列表。

### UX-P0-02：表单增加取消/返回与未保存确认

**问题**：新增/编辑页是长表单，当前缺少显式取消入口和未保存内容保护。用户误触返回可能丢失草稿。

**涉及文件**：

- `entry/src/main/ets/pages/ItemFormPage.ets`
- `entry/src/main/ets/pages/BatchFormPage.ets`
- `entry/src/main/ets/components/DeleteConfirmDialog.ets` 或新增通用确认组件

**修复方向**：

- 表单顶部增加“取消”或“返回”动作。
- 记录初始草稿和当前草稿，判断是否有未保存变更。
- 用户返回或取消时，若有变更则弹出“放弃编辑？”确认。
- 保存中禁用返回确认中的提交动作，避免重复提交。

**验收**：

- 新增物品输入名称后点取消，出现确认；选择继续编辑时保留输入。
- 编辑物品修改字段后返回，出现确认；选择放弃后返回来源页面且不保存。
- 未修改内容时返回不弹确认。

### UX-P0-03：返回刷新改成非阻塞刷新

**问题**：多个页面在 `onPageShow()` 中直接重新加载并显示整页 loading。实时性已解决，但用户返回页面时可能出现闪烁。

**涉及文件**：

- `entry/src/main/ets/pages/Index.ets`
- `entry/src/main/ets/pages/ItemListPage.ets`
- `entry/src/main/ets/pages/ItemDetailPage.ets`
- `entry/src/main/ets/pages/SearchPage.ets`
- `entry/src/main/ets/pages/BatchListPage.ets`
- `entry/src/main/ets/pages/LendingPage.ets`
- `entry/src/main/ets/pages/LocationManagementPage.ets`
- `entry/src/main/ets/pages/CategoryManagementPage.ets`

**修复方向**：

- 区分首次加载 `loading` 和已有内容刷新 `refreshing`。
- 页面已有数据时，返回刷新不清空当前数据，不展示整页 loading。
- 刷新失败时保留旧数据，并用轻量错误提示说明“刷新失败，可重试”。

**验收**：

- 从编辑页保存返回详情/列表：首页摘要和列表数据更新。
- 返回过程中旧内容不闪白、不被整页 loading 替换。
- 刷新失败时旧内容仍可见。

## P1：高频体验优化

### UX-P1-01：首页与全局导航重构

**问题**：首页同时承载新增、搜索、设置、位置、分类和摘要入口，入口较散。

**修复方向**：

- 建立底部导航或稳定主入口：`首页 / 物品 / 搜索 / 设置`。
- 提供全局新增按钮。
- 位置、分类管理收敛到设置或管理页，避免占用首页主路径。

**验收**：

- 用户从任意主页面都能在一步内新增物品。
- 首页首屏优先展示搜索、新增、临期和待处理信息。
- 设置和管理类入口不抢占核心物品路径。

### UX-P1-02：搜索改为即时反馈

**问题**：搜索页需要点击“应用搜索与筛选”后才看到结果，不符合找物品的高频预期。

**涉及文件**：

- `entry/src/main/ets/pages/SearchPage.ets`
- `entry/src/main/ets/service/SearchSuggestionService.ets`

**修复方向**：

- 名称输入使用防抖搜索。
- 位置/分类筛选点击后自动刷新结果。
- 已选条件以 chip 展示，可单独清除。
- 保留“查看列表结果”作为次要动作。

**验收**：

- 输入关键词后无需点按钮即可看到匹配项。
- 选择位置或分类后结果自动更新。
- 清除单个筛选条件后结果立即恢复。

### UX-P1-03：新增表单分层

**问题**：新增物品时照片、扫码、提醒、备注等内容与核心字段并列，增加首次录入负担。

**修复方向**：

- 首屏保留核心字段：名称、位置、数量、单位。
- 到期/提醒、照片/扫码、备注放入“更多信息”折叠区。
- 编辑模式默认展开已有内容所在的区域。

**验收**：

- 只填名称可以快速保存。
- 新增表单首屏不被低频字段占满。
- 已有照片、到期日或备注的物品进入编辑时，对应区域可见。

### UX-P1-04：日期、数量和提醒使用更合适控件

**问题**：到期日期使用 `YYYY-MM-DD` 文本输入，提醒天数和数量也主要依赖手输，容易出错。

**修复方向**：

- 到期日期优先使用已核验的系统日期选择控件；未核验前保留文本输入和清晰校验。
- 数量提供数字键盘、加减步进或快速归零。
- 提醒天数提供快捷选项：当天、提前 3 天、提前 7 天、自定义。

**验收**：

- 非法日期不会保存，并能指出具体字段。
- 常见提醒天数可一键选择。
- 数量为 0 的待补货语义清晰可见。

### UX-P1-05：统一成功、失败和耗时反馈

**问题**：不同页面的保存、删除、移除照片、批次操作反馈不完全一致。

**修复方向**：

- 成功操作统一 toast。
- 失败操作统一 inline 错误区，并保留用户输入。
- 耗时操作按钮显示 loading 文案并禁用重复点击。
- 删除成功返回上一页后仍给出轻量反馈。

**验收**：

- 保存、删除、批次新增/删除、移除照片都有明确结果反馈。
- 重复点击不会产生重复写入。
- 失败后可继续编辑或重试。

## P2：细节与可发现性

### UX-P2-01：物品卡片增加可点击提示

**问题**：`ItemCard` 整卡可点击，但缺少箭头或按压反馈。

**修复方向**：

- 卡片右侧增加进入详情的视觉提示。
- 增加按压态或轻微背景变化。

**验收**：

- 用户能直观看出卡片可进入详情。
- 长名称、长位置不遮挡状态和数量。

### UX-P2-02：详情页增强管理改为分段结构

**问题**：批次、借还等增强功能堆在详情页底部，可发现性弱。

**修复方向**：

- 详情页采用 `详情 / 批次 / 借还 / 记录` 分段或清晰入口组。
- 批次数量、当前借出数量等摘要直接在入口处展示。

**验收**：

- 用户进入详情后能快速发现批次和借还能力。
- 批次和借还数据变化后详情摘要实时更新。

### UX-P2-03：空状态按场景给出下一步

**问题**：不同空状态的动作不够精确，例如“暂无即将到期”不一定应该默认“查看全部”。

**修复方向**：

- “暂无物品”：新增物品。
- “暂无搜索结果”：清除条件或修改关键词。
- “暂无即将到期”：查看全部物品或新增带到期日的物品。
- “暂无批次”：新增批次。

**验收**：

- 每个空状态都只展示与当前场景直接相关的动作。
- 空状态动作不会打开错误页面或错误模式。

## 手工验收清单

- 无物品状态：首页点击新增，能进入新增表单并保存成功。
- 列表无物品状态：点击新增，能进入新增表单并保存成功。
- 筛选无结果：点击清除条件后显示完整列表。
- 新增表单：输入名称后返回，会出现未保存确认。
- 编辑表单：修改字段后取消，不会保存变更。
- 保存物品后返回列表：首页、搜索结果、详情摘要实时更新。
- 返回已有数据页面时不出现整页闪烁。
- 搜索输入关键词后无需额外确认即可看到结果。
- 删除物品、删除批次、移除照片、停用位置/分类都有明确反馈或确认。
