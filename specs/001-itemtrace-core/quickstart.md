# 验证指南：ItemTrace 本地物品追踪核心闭环

本指南用于每个阶段完成后的可复现验证。它不代表当前功能已经实现，也不声明未执行过的构建或
测试结果。实际命令必须在 Phase 0 由本机 DevEco Studio 环境确认后补充。

## 前置条件

1. 使用支持 HarmonyOS `6.1.1(24)` 的 DevEco Studio 打开项目根目录。
2. 确认 `build-profile.json5`、`entry/build-profile.json5`、根与 `entry` 的 `oh-package.json5`
   已被 IDE 正确识别，且选中的模块为 `entry`。
3. 准备一个声明为 phone 或 tablet 的模拟器/真机。设备应使用本地日期，以便验证到期状态。
4. 在首次实现 RDB 或系统能力前，记录 IDE 实际可用的构建、单元测试和 `ohosTest` 命令；当前
   已核验应用构建包装器，设备测试命令仍待确认，禁止将猜测的测试命令当作验证证据。

## 已核验的 Phase 0 命令

在项目根目录执行：

```text
hvigorw.bat tasks
hvigorw.bat assembleApp --no-daemon
```

两条命令已在 2026-06-20 成功执行。第二条命令完成应用构建并生成 `entry/build/` 产物；当前
未配置签名，因此构建会提示跳过 HAP/App 签名。该警告不阻塞本地编译，但真机安装前必须配置签名。
设备测试尚无已确认的命令行任务，暂通过 DevEco Studio 选择 `ohosTest` 目标执行；后续确认命令后
必须补充到本节。

## Phase 0：工程与 SDK 核验

1. 在 DevEco Studio 同步项目并构建 `entry`；确认初始应用能启动当前 `Index` 页面。
2. 核对模块类型为 Stage、主入口为 `EntryAbility`，目标设备包含 phone 与 tablet。
3. 对 RDB、Preferences、提醒/通知、相册、相机、Form Kit 与扫码逐项记录：SDK 文档来源、
   最小依赖、权限名、模块配置、取消/拒绝/失败表现和最小构建结论。当前 SDK 已发现前六项声明；
   扫码尚未确认可用能力。
4. 若任一阶段二能力无法核验，在计划/任务中保留其 Adapter 与应用内降级，继续 Phase 1，不调用
   该能力的具体 API。扫码当前必须保留手工输入降级。

## Phase 1：本地闭环验收

### 当前执行记录（2026-06-20）

- 已实现并通过 `hvigorw.bat assembleApp --no-daemon`：Item 模型与字段校验、RDB Schema v1、DAO/
  Repository、创建/编辑/删除、名称搜索、位置/分类筛选、到期状态、首页摘要以及首页、列表、详情、
  新增/编辑和搜索页面。
- 本机构建任务未暴露单元测试或 `ohosTest` 的命令行入口。因此，`entry/src/test/` 中的服务与校验
  测试、以及下列场景仍需在 DevEco Studio 选择 `ohosTest` 目标后实际执行；在结果产生前不得标记为
  已通过。
- 本次构建仍有既有签名、混淆与 Router 旧接口弃用警告。它们不阻塞编译；真机安装需要单独配置签名，
  Router 接口迁移需在后续有经核验替代 API 时处理。

### 场景 A：快速新增与持久化

1. 清空测试数据或使用全新应用数据。
2. 新增仅填写名称的物品并保存；确认数量为 1、单位为“个”，且首页/列表可见。
3. 新增完整物品：位置“厨房 / 冰箱 / 冷藏层”、分类“食品”、数量 2、单位“盒”、
   到期日、提前提醒天数和注意事项。
4. 关闭并重新打开应用；确认两条记录及完整字段仍存在。

### 场景 B：到期状态与首页摘要

1. 建立四条记录：无到期日、远期日期、有效提醒窗口内日期、过去日期；再建立一条数量为 0 的记录。
2. 确认状态分别为“无到期日期”“正常”“即将到期”“已过期”，数量为 0 的记录只出现在待补货摘要。
3. 确认首页各摘要最多展示 10 条，空分区有明确文字反馈。

### 场景 C：详情、编辑、删除

1. 从列表打开完整物品详情，确认位置路径先于分类展示且注意事项完整可见。
2. 修改数量和位置并保存，返回列表、搜索结果和首页确认更新一致。
3. 发起删除后先取消，确认记录仍在；再次确认删除，确认其从列表、搜索和首页消失，并说明不可恢复。

### 场景 D：搜索、筛选与错误

1. 创建至少 50 条名称、位置和分类不同的测试记录。
2. 以名称连续文字搜索，按位置、分类及两者交集筛选，确认 10 秒内可定位目标；清除条件后恢复完整列表。
3. 验证名称为空、超过 80 字符、数量为负数、提醒天数超范围和注意事项超长时均不能保存。
4. 用可控的测试替身验证数据库初始化或写入失败：页面显示中文错误、保留草稿、允许重试，且不把失败
   显示为成功。

### 自动化验证建议

- 在 `entry/src/test/` 覆盖：字段校验、有效提醒天数、到期状态、待补货判断、查询条件、Repository
  成功/失败和迁移顺序。
- 在 `entry/src/ohosTest/` 覆盖：路由参数、创建编辑删除、RDB 初始化、空状态、错误反馈和手机/平板
  关键布局。
- 每次变更后先运行本机已经确认的构建与相关测试；任何失败均须修复或记录阻塞原因、影响与复现步骤。

## Phase 2：系统能力验收

### 当前执行记录（2026-06-20）

- 已多次执行 `hvigorw.bat assembleApp --no-daemon`，最近一次在加入 Preferences、Reminder、Photo Picker、
  Form Kit、扫码降级和深色资源后构建成功。
- 当前命令行环境仍没有可直接执行的本地单元测试或 `ohosTest` 任务；下列验证需要在 DevEco Studio 配置签名后，
  使用 phone/tablet 模拟器或真机实际完成。不得把构建成功等同于系统授权、相册复制、提醒投递或卡片刷新成功。
- 当前已知构建警告包括 Router 旧接口弃用、现有 RDB 异常处理提示、未配置签名和工具链混淆提示；它们未阻断编译。

1. **Preferences**：修改默认提醒天数、排序、首页分区或主题后重启应用，确认偏好生效且 Item 数据不变。
2. **提醒/通知**：在设置页显式开启后新增带未来到期日的物品；验证创建、编辑重建、关闭/删除取消、授权拒绝、系统不可用和失败
   重试；拒绝后首页临期状态仍可见，且没有常驻后台任务。
3. **图片**：分别验证选择、系统 Photo Picker 的拍摄入口、取消、复制失败、替换和删除；确认图片仅保留在设备本地，
   不会改变未保存的表单字段。
4. **服务卡片**：确认只展示临期/今日提醒数量和打开应用入口；卡片不可用时主应用正常工作，且不泄露
   名称、位置、备注或照片。
5. **扫码与适配**：当前验证不可用提示和手工输入；后续可用扫码能力接入后再验证成功与取消。确认结果仅在用户确认后写入备注或搜索条件，
   不持久化物品编码；在手机、平板及可用折叠窗口中验证宽窄布局、长文本、深浅色与状态文本。

## Phase 3：迁移与增强验收

1. 使用含 v1 Item 的样本升级至包含 Batch、Location、Category 或 ReminderRecord 的数据库版本；
   验证旧数据完整、关系正确、失败可回滚。
2. 验证低库存阈值、借还、导入导出、备份恢复和搜索增强不会改变现有到期状态或隐私边界。
3. 使用本地样本验证导出/恢复的一致性；云同步、账号和多人共享没有独立规格前不得启用。
