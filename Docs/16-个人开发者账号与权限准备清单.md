## 2. 代理提醒的申请步骤

1. 以个人实名账号登录开发者平台，打开 `com.imotong.itemnest` 所在项目，查看“项目设置 → 开放能力管理 → 代理提醒”。记录入口是否可见及页面说明。
2. 准备真实的通用到期页面和提醒设置截图：例如化妆品和电池的到期日期、生产日期加保质期的计算结果、同日汇总与通知入口。材料说明用户主动设置的生活类临期提醒。
3. 在“APP → 应用上架 → 应用信息”核对与实际产品一致的应用分类，保存分类截图。官方指南列出的适用分类包括工具、效率、生活服务等，以最终产品分类和审批意见为准。
4. 在代理提醒申请页提交上述功能及分类材料。官方指南目前写明 8 个工作日内反馈，实际进度以控制台结果为准。
5. 审批通过后打开该能力开关并保存，重新生成和下载 Profile，以手动签名方式完成调试及发布配置，声明 `ohos.permission.PUBLISH_AGENT_REMINDER`。
6. 真机打开通知授权，创建一条未来提醒，记录返回 ID；退出应用后经过计划时刻，核对通知中心、横幅、锁屏与点击结果，分别填写实际结果。

公开指南明确临期场景与申请流程；个人账号的入口和最终准入仍需上述第 1、4 步核验。权益就绪前，产品通过系统日历完成系统侧安排。已保存的业务日期按同一套规则维护。[代理提醒官方指南](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/agent-powered-reminder)

## 3. 用户手机上的权限与访问

| 能力 / 条件 | 声明或系统访问 | 触发时机 | 用户当前选择下的操作 |
| --- | --- | --- | --- |
| 应用通知 / H11 权益就绪 | Notification Kit 通知授权；代理提醒声明 `ohos.permission.PUBLISH_AGENT_REMINDER` | 用户开启到期提醒且设备采用代理提醒 | 开启后登记；保留应用内关注与日历选项 |
| 系统日历 / H07 | `ohos.permission.READ_CALENDAR`、`ohos.permission.WRITE_CALENDAR` | 用户开启到期提醒且设备通过日历承接 | 授权后创建专属 LOCAL 日历，展示返回结果 |
| 语音填写 / H13 | `ohos.permission.MICROPHONE` | 用户点语音按钮 | 识别候选可编辑，文字输入始终可用 |
| 拍照 / H03 | CameraPicker 系统选择流程 | 用户点拍照 | 确认后将所拍照片加入当前草稿 |
| 相册 / H03 | PhotoViewPicker 所选资源授权 | 用户点从相册选 | 读取已选图片并复制到沙箱 |
| 扫码 / H12 | Scan Kit 默认界面预授权的相机访问 | 用户点扫一扫 | 系统界面返回码值；条码可手动输入、位置可列表选择 |
| 分享收图 / H05 | 系统分享授予的资源访问 | 用户分享图片到本应用 | 预览、确认并保存 |
| 备份 / H08、H09 | 系统文件选择器、系统备份设置 | 用户导出、导入或使用系统备份 | 本地文件预览与恢复；系统备份按设备设置执行 |
| 桌面卡片与快捷方式 / H06、H14 | 卡片添加流程、应用快捷方式配置 | 用户添加卡片或长按图标 | 直接进入对应任务，摘要内容由隐私开关控制 |

通知授权与代理提醒权益是两个独立条件：前者由手机用户决定，后者由开发者平台和签名决定。真实弹出形式、锁屏显示及提示音取决于系统通知设置。日历提醒还需核对系统日历的通知设置。[通知概述](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/notification-overview)

## 4. 设备与模型准备

开发前核对 DevEco Studio、HarmonyOS SDK、API 26 声明、真机型号与系统版本。Core Vision 文字识别记录初始化结果；Core Speech 记录 `zh-CN` 离线模型创建结果及麦克风授权；Scan Kit 使用 API 26 的默认扫码支持查询。HDS、Core Speech 等能力的服务区域按照对应官方说明核对。

同一次真机验收分别记录：能力查询成功、接口调用成功、页面显示正确、实际业务结果成立。模型待就绪时，产品提供照片、文字和位置选择路径。完整步骤见 A06、A25—A32。
