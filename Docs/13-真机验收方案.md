# 真机验收方案

版本：1.1 · 2026-11-01。验收在连接手机上手工执行，证据使用现场观察文字、日志和计时记录。本文件定义 A01—A32 的操作步骤；本轮已执行结果和剩余分支统一记录在 `19-原生应用真机验证记录.md`。

## 1. 验收记录方式

每轮先记录：执行日期、执行人、手机型号、系统版本、API 级别、应用版本与构建标识、屏幕刷新率、字体大小、明暗主题、系统动态效果设置、数据数量和权限状态。影响实际结果的环境变化写入对应条目。

每项记录格式：

| 字段 | 填写内容 |
| --- | --- |
| 编号与需求 | A 编号及 F / H / M 编号 |
| 前置条件 | 数据、位置、权限和当前页面 |
| 实际步骤 | 本次真实执行的动作与输入 |
| 预期结果 | 对应产品规则及可观察结果 |
| 实际结果 | 实际文字、状态、数量、耗时 |
| 状态 | 已通过 / 待验证 / 待修正 |
| 证据 | 现场观察记录、日志路径或测量结果及时间 |
| 后续处理 | 差异原因、修改位置与复验条件 |

## 2. 核心任务验收

| --- | --- | --- |
| A01 首次记录 / F01、M01 | 使用空数据打开；阅读首页；记录身边的一件物品；查看回执再搜索 | 用户理解从哪开始，正式记录出现；示例有独立标识；记录用时、询问次数和用户认为的收益 |
| A02 最小输入 / F02、H03 | 分别保存仅名称、仅照片、名称加照片；观察保存前后 | 三种有效方式均成立；纯空输入提示保存条件；照片显示名、数量与详情一致 |

| A08 找到与移位 / F04、F06、M07 | 从搜索打开物品；点击找到了；改到另一抽屉；回到原搜索和位置 | 确认时间和路径正确；检索立即反映新位置；查看与确认时间各自准确 |
| A09 数量与借出 / F08 | 3 件拆出 1 件；借出新记录；归还到另一位置；将剩余记录数量改为 0，再恢复 | 数量守恒、照片可见、来源可追溯；借出与归还明确；用完归档数量 0，恢复填写有效数量 |
| A10 一次提醒 / F09、H07 | 开启日历；设置两个同日提醒；修改一个日期；处理另一条；经过实际提醒时刻 | 同日对应一条日程；内容随操作变化；每个日期版本一次安排；记录系统通知实际出现情况 |
| A11 桌面卡片 / F11、H06 | 添加 2×2、2×4 卡片；分别点找东西、记一件；开启 3 条摘要并点击；关闭摘要 | 路由与当前任务正确；默认通用入口；摘要随隐私设置与数据刷新 |
| A12 导出恢复 / F12、H08 | 导出带中文、逗号、换行和照片的完整备份与 CSV；修改一条；导入并核对冲突；执行明确选择 | 文件可读，数量和图片可核对；冲突默认保留当前；选择备份版本后对应数据正确；CSV 按文本显示 |

| A16 编辑照片 / F06 | 调整主图和顺序；编辑名称；单件改组再改回；返回后继续编辑 | 表单与正式记录的提交时点清楚；照片顺序一致；类型数量转换符合规则 |
| A17 权限与日历状态 / F09、F15 | 开启日历时选择当前权限；记录日期；在系统设置改变权限后回来；重新开启 | 日期始终可在应用内关注；系统安排状态准确；清理及重新授权操作可执行 |
| A18 批量整理 / F07 | 在筛选结果选多条与全选；核对总数；统一改位置；统一回收 | 确认集合与结果一致；筛选与列表更新；受影响记录历史完整 |

| A26 系统代理提醒 / F09、H11 | 已获权益、签名及通知授权；保存两个同日日期；退出进程后经过真实计划时刻，点通知；另行记录重启后表现 | 同日一条通知；点击 P12；登记状态与实际出现分别记录；进程结束及重启各有实际证据 |

| A30 扫码返回 / F17、H12 | 扫描首次码值、取消扫码、手动输入含前导零码值，查看后返回原任务 | 首次码值可继续名称或照片保存；前导零保留；取消与返回保留任务 |

## 3. 用户是否愿意用：任务研究

邀请 5—8 位愿意参与的个人用户，用自己的物品完成四个任务。先让参与者用自己的语言描述最想解决的问题，再给出任务，观察者记录行为和原话。

| 任务 | 观察重点 | 设计目标 |
| --- | --- | --- |
| 记住一件以后会找的东西 | 从哪里开始、主动填写哪些信息、第一次收益是什么 | 首条记录 60 秒内完成，用户能说出以后怎样找到它 |
| 整理一个抽屉 | 整组与单件如何选择、是否重复选位置、何时想结束 | 连续 3 件只选择一次位置；整理范围由用户自己决定 |
| 几天后找一件东西 | 使用名称、别称还是位置；结果是否帮助找到实物 | 100 条数据场景寻找中位时间目标 10 秒 |
| 物品搬到别处 | 是否自然想到更新、入口是否可理解、操作负担 | 更新位置中位时间目标 10 秒 |

熟悉用户的“名称 + 已有位置”记录中位时间目标为 15 秒。目标用于判断设计，实际结果逐条记录。隔 7—14 天回访时询问记录是否帮助寻找、是否更新过位置、哪一步值得继续保留；回访频率服务于研究本身。

## 6. 本轮产品观察补充

参与者在录入自己的一件有期限的物品时，选择直接日期或生产日期加保质期。观察是否能看懂计算结果、是否理解到期提醒、是否愿意保留这条记录；到期后观察是否能从提醒进入并完成处理。记录包括系统授权步骤在内的总成本。扫码与语音分别和直接输入比较完成时间、修正次数和用户自主选择，观察结果再决定入口是否值得突出。当前状态为待用户体验验证。
