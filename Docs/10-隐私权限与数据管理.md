# 隐私、权限与数据管理

版本：1.1 · 2026-11-01。关联 F12、F13、F15，页面 P12—P15，系统能力 H03、H05—H09、H11—H14。

## 1. 用户能理解的数据承诺

“你的家当保存在这台设备中。照片、名称和位置帮助你记住物品；你可以制作完整备份，也可以通过系统备份和换机继续使用。”

产品以本地使用为基础。名称、照片、位置、借出称呼、日期和搜索历史在应用沙箱中保存；文字识别使用设备上的官方能力。用户开启到期提醒后，汇总数量与提醒日期进入系统通知或专属日历；开启详情后附上物品名称；用户导出的文件由其选择保存位置。系统备份与换机按系统设置和授权处理应用数据。

## 2. 数据流转与用户控制

| 数据 | 保存与处理位置 | 用户控制 |
| --- | --- | --- |
| 物品与位置 | 应用本地数据库 | 编辑、归档、回收、导出和恢复 |
| 照片 | 应用沙箱资源目录，设备端生成缩略图 | 添加、设主图、移除；完整备份携带照片 |
| 原始识别文本 | 当前识别会话与草稿候选区 | 选择需要的片段；正式记录只保存已采用字段 |
| 搜索历史 | 本机设置，最多 8 条 | 单条清除、全部清除 |
| 提醒内容 | 用户授权后的系统通知或应用专属日历 | 到期提醒开关；默认数量与日期，详情开关控制物品名称 |
| 语音 | 设备上的离线识别会话 | 点语音后申请麦克风；候选确认后进入字段，录音随会话释放 |
| 商品条码 | 本地物品字段及查询 | 通过默认扫码取得码值，查看已有记录或确认新建 |
| 桌面摘要 | 用户添加的应用卡片 | 默认通用入口；主动开启最多 3 条常用摘要 |
| 导出文件 | 用户选择的保存目录 | 查看位置、分享、移动或删除文件 |
| 系统备份 | 系统备份服务按设备设置管理 | 在系统提供的备份与换机入口操作 |
| 本地诊断 | 用户发起导出时生成 | 预览字段，选择保存位置 |

完整备份文件包含个人记录，导出前提示“这份文件包含物品照片、位置和借出信息，请选择自己信任的保存位置”。手动备份为可迁移的标准归档格式，系统文件保护取决于用户选择的存储位置。

## 3. 权限时机与页面文案

| 触发 | 系统访问方式 | 页面解释与继续方式 |
| --- | --- | --- |
| 点击拍照 | CameraPicker 返回所拍图片 | “拍张照片，就能先记下来”；取消后继续原表单 |
| 点击相册 | PhotoViewPicker 授予所选图片的访问 | “选几张能认出它的照片”；选取后复制到草稿 |
| 系统分享图片进入 | Share Kit 临时资源访问 | “把照片记进家当”；先预览再保存 |
| 开启到期提醒，采用日历承接 | READ_CALENDAR、WRITE_CALENDAR | “将到期日期写入系统日历，用于提醒”；当前选择保留应用内列表 |
| 开启到期提醒，代理能力就绪 | 通知授权、PUBLISH_AGENT_REMINDER 权益声明 | “到期当天提醒你”；返回实际安排结果 |
| 语音填写 | MICROPHONE | “说出名称或说明，确认后填入”；继续文字输入 |
| 扫码 | Scan Kit 默认界面预授权访问 | “扫一扫，看看自己是否记过”；取消后回原任务 |
| 选择备份文件 | 系统文件选择器 | 展示文件名和恢复预览 |
| 保存备份与清单 | 系统文件保存选择器 | 用户指定位置，成功后展示结果 |

Picker 与系统选择的临时访问范围按华为官方权限指南接入。权限申请绑定用户当次动作，日历说明中写明将同步的内容。[权限申请说明](https://developer.huawei.com/consumer/cn/doc/doccenter-app-security/bpta-permission-application)

关闭到期提醒时清理尚在未来的代理任务或应用日程，保留应用内日期。当前权限允许时立即完成清理；需要系统授权时展示“未来日程待清理”，提供重新授权和打开系统日历的操作。已经经过提醒时刻的日程作为用户日历历史保留。

## 4. 完整备份格式 v1

文件名为 `我的家当_YYYYMMDD_HHmm.itemnest`，内容为 UTF-8 JSON 与图片资源组成的 ZIP 归档。扩展名表达产品备份，`manifest.json` 表达可校验格式。

```text
manifest.json
data/locations.json
data/items.json
data/item-photos.json
data/item-dates.json
data/change-events.json
data/drafts.json
data/preferences.json
assets/<asset-id>.<ext>
```

manifest 必填：`format="itemnest"`、`formatVersion=1`、`schemaVersion`、`appVersion`、`exportedAt`、`datasetId`、`counts`、`files`。counts 分别列出单件、整组、归档、回收站、位置、草稿、图片数量。files 每项包含相对路径、字节数、SHA-256；资源表通过 item-photos 与资产描述关联。

每个数据文件使用 `{"schemaVersion":1,"records":[...]}` 结构，records 中的字段与 `09` 对应；preferences 使用同一封装，records 包含一条偏好对象。manifest 的 schemaVersion 与所有数据文件版本一致。datasetId 在第一次建立自己的家当时生成 UUID，合并时保留当前值，替换时采用备份值。图片资产描述放在 manifest 的 `assets` 中，字段与 `09` 的 Asset 对应。资源路径固定在 assets 目录，导入器按清单映射生成自己的沙箱路径。

备份读取同一数据快照，期间用户的新编辑进入下一版本；界面展示快照生成时间。引用的媒体在打包完成或取消前保持可读取。完成压缩与完整性校验后写入用户选择的目的地，记录真实文件名、大小和生成时间。

包含：正式记录、位置、日期、照片、变化记录、草稿、归档、仍在保留期的回收站、主题与常用偏好。设备相关的日历 ID、代理提醒 ID、通知授权状态、卡片实例 ID、临时 URI 与缩略图缓存通过恢复后的当前环境重建。

## 5. 恢复的完整过程

1. **选择与校验。** 读取 manifest，核对格式、版本、路径、字节数与校验值，逐个检查实体字段和引用。预览前完成必要校验。
2. **展示预览。** 显示来源应用版本、备份时间、全部数量、预计新增与冲突数量、照片状态、空间需求。解析出的文字作为普通内容展示。
3. **选择方式。** 默认“合并到当前家当”；另一个选项为“用这份备份替换当前家当”，附当前和备份数量。
4. **确认差异。** 合并预览列出同 ID 内容差异，默认保留当前版本。用户可以逐项选“使用备份版本”，也可以明确应用同一种选择到全部冲突。
5. **保存。** 在暂存区构建完整目标数据，校验关系与媒体，原子切换为正式数据；进度按读取、核对、保存三个阶段显示。
6. **结果。** 显示新增、更新、保留、图片待补充、未来日历待安排数量；提供“查看家当”和“查看恢复记录”。

替换前在应用内生成一份保护快照，检查可用空间，显示“本次替换前的数据将保留 7 天，可在数据管理中恢复”。用户明确确认后替换。保护快照最多保留最近 1 份；下一次替换前允许先导出已有快照，再生成新的保护快照。

## 6. 合并的确定规则

| 对象与情况 | 规则 |
| --- | --- |
| ID 相同、规范化内容相同 | 保留当前对象，计入“已存在” |
| ID 相同、内容不同 | 进入冲突预览；显示双方修改时间、名称和状态；按用户选择保留完整对象 |
| ID 全新 | 作为新增候选，校验引用后导入 |
| 位置 ID 全新但同父级同名 | 映射到已有位置；下级按映射后的父节点继续处理；备注和照片差异进入预览 |
| 相同 ID 位置移动 | 随用户选择的版本更新父节点，预先校验 4 层和同级名称 |
| Item 存在冲突 | Item、照片顺序、日期及对应变化记录作为一个版本单位选择 |
| 资产内容相同 | 用 SHA-256 与字节校验复用资源，重新建立引用 |
| 草稿 ID 相同 | 默认保留当前草稿；用户可将备份草稿作为一条新草稿导入 |
| 主题和卡片偏好 | 合并保留当前设置；替换采用备份设置，卡片实例按当前设备重新关联 |
| 日历状态 | 日期和处理状态保留；未来系统安排按当前权限和时区重建 |

仅有照片的记录在恢复后仍须满足最小有效条件。照片文件缺失时，预览列出具体记录，提供重新选择完整备份或为该条补写名称后继续。具有名称且部分照片待补充的记录可以由用户确认导入，原图占位显示对应状态。

回收站截止时间按备份中的实际时间判断；预览显示已经超过保留期的数量，用户可选择将这些记录恢复为普通记录后导入。默认合并范围为有效记录及仍在保留期的数据。

## 7. 文件读取边界与空间

导入逐项验证相对路径处于约定目录，使用系统解码器验证图片内容，检查 JSON 类型、长度、枚举和引用。预检累计解压字节数与资源数量，按“归档体积 + 解压数据 + 目标数据增量 + 保护快照 + 20% 余量”估算所需空间。单文件达到 2GB、实体达到 10 万条或单图超过 `09` 限制时，停止在预览阶段并提示选择较小备份或先在来源设备分批整理；用户原数据保持当前可用版本。

格式版本高于当前支持范围时显示来源版本与“更新应用后恢复”。文件内容存在问题时标明对应文件或记录，提供重新选择入口。取消读取或取消确认后返回数据管理，当前数据仍是原有版本。

## 8. 清单导出

UTF-8 CSV 带 BOM，表头固定：记录 ID、名称、记录类型、数量、状态、位置、分类、标签、备注、借出称呼、到期日期、保修日期、归还日期、更新时间。默认导出当前在手与借出；用户可选加入归档。回收站通过完整备份保存。

标签用中文顿号连接；字段按 CSV 双引号规则转义换行、逗号和双引号。以公式控制字符开头的用户文本按文本单元格方式转义，便于在表格软件中安全阅读。CSV 用于阅读和交换清单；恢复以 `.itemnest` 文件为入口。

## 9. 回收、资源和诊断

移入回收站时保留 30×24 小时，页面以当地日期显示截止时刻。应用启动、数据管理打开和维护任务执行时清理已过保留期的记录。永久删除展示名称、照片引用影响与操作后结果，用户确认后删除对应业务数据，并清理全部引用已释放的媒体。

系统备份和用户导出文件由相应存储位置管理；本地删除作用于当前应用数据。P13 同时提供备份文件位置和系统备份说明，帮助用户管理自己的副本。

诊断文件只包含应用版本、系统版本、API 级别、设备能力开关、错误代码、发生时间及经过脱敏的操作类型。用户在 P19 查看内容并主动导出。产品使用研究的计时和观察记录由研究参与者明确同意后采集，记录范围见 `02`。

## 10. 日期与扫码字段的备份

首版备份使用 formatVersion=1、schemaVersion=1，完整保存 expiryInput、商品条码、到期提醒偏好和外部详情开关。日期统一采用当天提醒。恢复后保留用户填写的日期依据与处理状态，设备登记标识按当前环境重建。外部详情默认关闭。

CSV 在现有列后追加“日期填法、生产日期、保质期数值、保质期单位、条码类型、商品条码”，使期限待补充的记录也可读。语音候选与原始音频属于会话内容；正式备份保存用户采纳的文字。
