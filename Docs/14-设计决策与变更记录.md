下列内容为本套文档采用的可实施方案。用户研究与真机数据用于后续校准，设计状态与实测结果分别维护。

| 编号 | 决策与理由 | 对应内容 | 验证与调整依据 |
| --- | --- | --- | --- |
| B01 | 用“记住放哪，用好已有”表达价值，先解决一次真实寻找 | M01、F01、P01 | 首次任务能否让用户理解收益 |
| B02 | 名称或照片即可成为正式记录；位置按当前意愿补充 | M02、F02、P03 | 首次记录耗时与后续可找回程度 |

| B04 | 连续记录只复用位置与类型，下一件保持清楚的输入上下文 | M04、P03 | 连续三件的操作次数、位置错误率 |
| B05 | OCR 产生可选候选，名称由用户最终决定 | M05、H04 | 候选采纳率、修正时间与标签图实际效果 |
| B06 | 搜索匹配生活用语和完整位置，“找到了”轻量确认 | M06、F05 | 隔日寻找与位置可信度 |
| B07 | 借出、归还、用完、移位形成具体状态变化，维护入口跟随详情 | M07、F08 | 用户真实变化后能否顺手更新 |
| B08 | 录入时确定到期日，到期当天提醒一次，同日汇总到一个系统任务 | M08、F09、H07 | 实际日历内容与通知观察 |
| B09 | 本地记录、手动完整备份与官方系统换机共同形成长期保存路径 | M09、F12 | 文件恢复与系统恢复的实际数据核对 |
| B10 | 三个目的地“家当、位置、我的”，记录为独立的随手动作 | P01、P07、P11、C02 | 用户能否准确找到高频入口 |

## 3. 待取得的验证证据

| 主题 | 已具备依据 | 下一步需要的证据 |
| --- | --- | --- |
| 用户动机 | 场景分析与可操作原型 | 5—8 人真实物品任务及 7—14 天回访 |
| 酷安动态参数 | 实际关键页面与交接截图 | 连续录屏、逐帧时长、触觉观察 |

| OCR | 官方接口与候选规则 | 目标手机模型就绪、常见标签识别耗时和质量 |
| 到期提醒 | 官方日历、代理提醒与通知资料，统一日期算法 | 个人代理权益、签名与授权、关闭应用后的实际提醒；日历路径的实际结果 |
| 扫码与语音 | 官方默认扫码、离线语音接口 | 真实码值、模型条件、录入与修正总成本 |

## 4. 变更维护规则

每次变更写明触发原因、用户问题、决定、受影响的需求/页面/字段/验收项、数据兼容方式与实际验证状态。需求改变先更新 `03`；字段或业务状态改变同步 `09`、`10`；页面改变同步 `05` 和原型；系统能力改变同步 `08`、`11`。

单个主题的详细规则只在负责它的文档维护，其他文档通过编号引用。设计参数、官方事实和用户实测各自保留来源。
