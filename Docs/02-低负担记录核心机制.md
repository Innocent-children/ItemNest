# 让用户愿意记录：核心产品机制

版本：1.1 · 2026-11-01。本文定义机制 M01—M09；字段与计算规则由 `09-数据模型与业务规则.md` 统一维护。

## 1. 从用户的投入与回报出发

用户记录的目的，是减少将来寻找、重复购买和遗忘状态的麻烦。记录当下需要付出时间，价值却经常在以后发生。产品的核心任务，是缩短这两者之间的距离，让每次少量投入都能形成马上可用的结果。

需要分别处理四种成本：想起要记的成本、动手录入的成本、事后补充的成本，以及物品变化后的维护成本。只要其中一项长期过高，记录就可能停下来。因此，设计同时覆盖“什么时候出现”“最少填什么”“保存后得到什么”“以后怎样更新”。

以下机制是本版产品方案。它们的效果通过真实任务观察验证，当前状态为待用户体验验证。

## 2. M01：让用户从一件值得记住的物品开始

**动机：** 用户刚收起一件以后会找的东西，此刻知道它的外观和位置。

- 首屏文案：“先记一件你以后会找的东西。”主操作：“记下一件”。
- 示例使用充电器、备用钥匙、保修卡、换季用品，帮助用户把需求对应到生活场景。
- “看看示例”进入独立示例视图，顶部持续标注“示例”，返回自己的家当后继续空数据流程。
- 首次保存成立后，展示这件物品和位置；位置为空时展示“已记下，随时可以补上位置”。
- 回执提供“查看这件”和“继续记下”。首次命名记录还提供一次“试着找一下”，打开已带入名称的搜索结果。

**验证：** 用户能否在首次使用时自行选择一件物品、完成保存，并解释这条记录将怎样帮助自己。验收 A01、A02。

## 3. M02：用最少的信息形成一条可用记录

保存条件为：用户提供了名称或至少一张已成功读入的照片。单件与整组都适用。

| 用户提供的信息 | 保存后的呈现 | 已经可以完成的事 |
| --- | --- | --- |
| 仅名称 | 名称 + 类型图形 +“添加位置”入口 | 按名称搜索、以后补图 |
| 仅照片 | 主照片 +“照片记录 · 月日时分”显示名 | 从最近记录和位置中凭外观查找 |
| 名称与位置 | 名称 + 完整位置路径 | 搜索后直接去对应位置寻找 |
| 照片与位置 | 照片 + 位置路径 | 凭外观浏览和定位 |
| 名称、照片与位置 | 完整识别信息 | 文字查找与外观确认相互补充 |

自动显示名只承担列表识别职责。名称字段由用户输入或明确采纳候选时填写。用户从保存成功那一刻就拥有正式记录，详细信息可随使用逐步丰富。

录入面板首层只展示照片、名称、位置和“记一件 / 记一组”；数量、分类、标签、日期和备注收在“更多信息”。进入文字输入时使用系统输入法，用户可沿用手机提供的语音输入。

名称、整组说明和搜索框另提供应用内语音入口。用户说完后查看可编辑文字，点击采用完成输入。语音用于当前字段；录音、识别和采纳的状态在 P23 连续呈现。设备条件与接口见 H13。

**验证：** 从点击“记下”到保存成功，纯文字路径的核心操作为打开、输入、保存；照片路径包括系统拍摄与确认，按真实动作计时。验收 A02、A03。

## 4. M03：让一组物品也能先被记住

**动机：** 面前是一箱物品，用户希望先记住“这箱里大致有什么”。

- 选择“记一组”，拍摄全貌和必要的局部照片，可输入“露营箱”等名称。
- 添加“炉头、气罐、折叠碗”等可搜索的内容说明，照片与说明共同帮助查找。
- 记录在所有列表中显示“整组”；数量显示“1 组”，组内件数由用户在说明中表达。
- 搜索命中组的说明时显示“在整组说明中找到：折叠碗”，打开后展示整组照片和位置。
- 用户希望精细记录某件物品时，从组详情选择“在此位置记一件”，复用位置并生成独立记录；原组说明由用户按实际内容调整。

**收益：** 用户可以先建立可用的存放线索，再按常找、贵重、借出或有日期的物品逐渐增加精度。统计始终分别展示单件记录和整组记录。

**验证：** 用户整理一箱物品时能否自主选择整组方式，以及一周后能否根据照片与说明找到其中指定物品。验收 A05。

## 5. M04：连续记录复用同一处的上下文

**动机：** 用户正在整理同一抽屉，希望连续记下几件物品。

从位置详情进入“在这里记下”，录入面板显示固定的位置条。保存后选择“继续记下”，复用位置、记录类型和用户开启的连续模式；名称、照片、数量、借出对象和日期回到各自初始值。

位置条始终可见，用户可以随时切换。“完成这次整理”关闭连续模式；从全局入口重新开始时，展示最近使用的位置供选择。全局入口以用户本次的明确选择确定位置。

会话回执展示“这次在书桌抽屉记下了 4 条”，每条记录保存后立即生效。中途离开时，已保存的记录继续可用，当前输入进入本地草稿。

**验证：** 连续记录三件物品时的位置选择次数为 1；第二、三件的名称、日期和数量各自正确。验收 A04。

## 6. M05：智能建议节省确认成本

智能能力承担“把已看见的信息变成少量候选”的工作。

- 用户拍摄包装或票据后，点击“提取照片文字”，从照片中选择名称、备注或日期文本。
- 候选有明确来源，点击后写入对应字段；用户已有内容保留为当前值，替换由这次点击表达。
- OCR 原文与提取结果保存在当前编辑会话，用户采纳的内容进入正式字段。
- 时间较长时，页面继续提供保存；用户离开后，候选结果只更新对应草稿的候选区。
- 内容识别受图像和设备条件影响时，界面提供“输入名称”“保留照片”“重新拍摄”。

一次至多展示 3 条名称候选；候选顺序优先为用户选择的文本，再按文本行阅读顺序。日期候选仅解析完整年月日，包装中的生产日期和保质期交由用户选择对应含义。具体解析规则见 `09`。

**验证：** 用清晰包装、反光包装、无文字物品分别操作；用户能看懂候选来源、完成纠正，并独立完成保存。验收 A06。

## 7. M06：每次查找都让记录显出价值

搜索框位于家当首页首屏，桌面卡片也提供“找东西”。用户可以输入名称、别名、备注、标签或位置中的关键词。

结果首先呈现图片、名称、状态和完整位置路径。单件数量作为辅助信息；借出记录显示借给谁；整组显示命中的说明片段。用户记得的是外观时，可以按位置看照片。

详情的“找到了”操作更新最后确认时间，并提供一句轻量反馈：“位置已确认”。它由用户在实际找到后主动触发。仅浏览详情只更新最近查看时间。

搜索结果为空时，显示“试试物品的别称，或按位置看看”，保留当前词，并提供“按位置找”“用这个名称记下”。这份结果表达的是当前记录中的匹配情况。

**验证：** 以同义称呼、备注关键词、位置名和外观线索寻找已记录物品；观察用户是否将查询结果理解为自己当前记录的范围。验收 A07。

## 8. M07：把维护动作放到变化发生的地方

| 物品变化 | 用户入口 | 保存后的明确反馈 |
| --- | --- | --- |
| 换了存放处 | 详情“改位置”，位置页批量选择 | 展示新位置，并在原列表即时更新 |
| 借给朋友 | 详情“借出”，填写称呼 | 状态显示“借给小林”，原位置保留为归还参考 |
| 收回物品 | 详情“已归还”，确认放回位置 | 状态回到在手，显示当前数量和位置 |
| 用掉一部分 | 详情“调整数量” | 显示新的数量和本次变化 |
| 已经用完或送出 | 详情“归档” | 进入历史记录，搜索可切换查看 |
| 发现曾经记错 | 详情直接编辑 | 保存后所有入口使用更新后的信息 |

位置过时的提示只有在用户需要判断时出现。详情展示“位置确认于 10 月 12 日”，用户可以直接更新。长期空闲后再次打开，首页继续呈现已有记录和查找入口。

**验证：** 找到物品后移到另一处，再次搜索应呈现新位置；借出归还可从同一详情完成。验收 A08、A09。

## 9. M08：提醒只承担用户交付的具体事情

用户在录入物品时填一个到期日期，或者填生产日期和保质期，应用计算到期日期。保存后，在到期当天上午 09:00 提醒一次；同日合成一条。任意分类的物品都适用。P20 是录入表单中的日期区，计算结果随输入显示，与物品一起保存。

首次使用到期提醒时，应用结合实际能力给出一次系统授权说明，后续有日期的物品沿用设置。用户看见“到期提醒”和具体日期，系统承载选择由 H07、H11 处理。生产日期暂缺时保留已填的保质期，提示“补上生产日期可计算到期日”，物品本身可以正常保存。

提醒入口提供查看、修改日期和处理完成；用户从提醒进入详情后，可以顺手调整数量或归档。P21 显示开启状态和需要处理的安排结果。每一次回到应用都围绕用户已经想做的事情。

**验证：** 同一天有三件物品需要留意时，用户收到一条汇总；查看后能逐件处理。验收 A10。

## 10. M09：让长期投入有归属感

用户随时可以导出清单、制作完整备份，并在换机后恢复。数据管理页说明照片、记录和系统日历分别保存在哪里。用户的物品照片成为界面的主角，已有记录能持续使用。

用户在外部图库中选好照片后，可以通过系统分享送到“我的家当”，继续已有的整理动作。分享确认页清楚区分“每张记一件”和“合成一组”，保留来源与数量预览。

桌面图标提供“记一件、找东西、看临期、扫一扫”四个快捷方式。商品条码连接本地同款记录，用户可查看已有记录或“再记同款”；新记录复用名称、分类与条码，日期由本次物品决定。扫码作为查找和复用的可选入口，首次录入仍以名称或照片成立。F17、H12 定义本地匹配，A29、A30 观察总操作成本。

**验证：** 用户能够解释备份文件的作用，并通过恢复预览确认记录与照片会怎样进入当前家当。验收 A11、A12。

## 11. 将机制组合成用户眼前的下一步

用户愿意继续使用，来自“这次记录确实帮到了我”的经验。产品根据当前任务提供最有用的一步，保存条件保持稳定，用户随时可以结束这次整理。

| 当前情境与输入 | 页面采用的规则 | 用户马上得到的价值 | 后续自然发生的动作 |
| --- | --- | --- | --- |
| 第一次打开，自己还没有记录 | P01 提供一件有意义的起点，P03 接受名称或照片 | 一条属于自己的可用记录 | 查看回执；命名记录可立即试着搜索 |
| 有未完成草稿，用户回来继续 | P01 突出最近草稿；原照片、文字和位置可继续使用 | 上次投入仍然有效 | 补上当前想到的信息并保存 |
| 正在整理某个位置 | P08 进入 P03，位置始终可见 | 只决定本次物品怎样记 | 保存、继续下一件或完成这次整理 |
| 面前是一箱杂物 | 单件与整组并列提供，说明支持生活用语 | 先记住整箱的外观、内容线索与位置 | 实际需要某件时再建立独立记录 |
| 准备寻找或购买某件东西 | P02 按自己的称呼查找，结果直接呈现状态与位置 | 知道当前已经记下什么、放在哪或借给谁 | 找到实物；确认位置或更新变化 |
| 刚把物品放到另一处 | 详情提供“改位置”，多件使用 P10 | 下次寻找能得到新的位置 | 完成后继续当前生活任务 |
| 已经过一段时间再次打开 | P01 保留已有家当、查找和草稿入口 | 过去的记录马上可以继续使用 | 按这一次实际需要查找或补记 |

首页信息的优先关系为：搜索与记下保持可达；最近草稿承担继续任务入口；当天日期摘要连接用户已设置的事情；物品内容承担主要浏览空间。草稿与日期摘要各占一条简短入口，详细内容分别在 P11、P12 展开。

首条回执强调已保存的具体对象，连续回执强调这次位置与已保存条数，维护反馈强调新的位置或状态。这三类反馈都指向用户实际获得的信息。

## 12. 一段完整的生活场景

下面是用于检验设计的情境示例，属于产品推演。

周日，用户把旅行充电器收进书桌抽屉。他拍一张照片，选择“书房 / 书桌抽屉”，保存后立即看见这条存放线索。抽屉里还有备用电池，他点击“继续记下”，原位置已经带入，拍照保存即可完成第二条。剩下的一袋配件以“旅行配件袋”整组记录，说明里写上“转接头、短线、读卡器”，这次整理便有了一个自然的结束点。

几天后准备出差，他搜索“读卡器”，从整组说明找到配件袋；点开照片确认外观，再按位置取出。后来把袋子放进玄关小柜，就在详情中修改位置。这条记录先帮他完成了一次寻找，随后的一次更新又为下次寻找留下了准确线索。

这段场景的三个收益分别是记住位置、成功找到和保持准确。记录数量随真实需要增长，整理粒度由用户决定。桌面卡片和系统分享负责缩短进入这些任务的距离。

## 13. 设计目标与测量方法

下表为首轮设计目标，验证状态均为待用户体验验证。计时从可操作页面出现开始，计入用户思考、系统选择器操作和确认步骤；同时单独记录系统等待时间。

| 指标 | 初始目标 | 测量任务与条件 |
| --- | --- | --- |
| 首次形成有用记录 | 60 秒内保存一条名称或照片记录，并能说明用途 | 首次接触，使用自己的物品，保留真实的权限和输入法过程 |
| 熟悉后的文字记录 | 中位耗时 ≤ 15 秒 | 完成一次熟悉操作后，记录一个名称与已建位置 |
| 连续记录 | 3 件物品只选择一次位置 | 同位置，每件独立保存，保持真实拍摄和确认步骤 |
| 找到已记录位置 | 中位耗时 ≤ 10 秒 | 100 条记录，提供用户自己使用的称呼 |
| 更新位置 | 中位耗时 ≤ 10 秒 | 从详情开始，目标位置已存在 |
| 保存正确性 | 每次明确保存对应一条正确记录 | 快速重复点击、切换前后台、连续录入 |
| 长期准确性 | 体验一周后记录可帮助完成再次寻找 | 记录被找到、位置变化、用户修正及原因 |

数值只是检验设计的起点。出现耗时较长时，记录具体是找入口、想名称、选择位置、系统等待还是理解反馈造成，再调整对应环节。体验者的真实叙述与操作证据保存在 `13` 的记录表中。

## 14. 如何判断用户真的愿意继续

产品质量以真实任务完成情况来判断。用户来得较少也可能是记录已经稳定，观察时结合是否发生寻找、收纳或借出等实际机会解释使用频率。

| 观察到的情况 | 需要追问和核对的事实 | 优先调整的产品环节 |
| --- | --- | --- |
| 用户打开后很快离开 | 当时想记什么，是否理解从一件开始，是否找到入口 | 首屏示例、价值文案与主操作 |
| 输入一半停下来 | 停在哪个字段，是否认为需要一次填完，草稿是否帮助继续 | 首层字段、选填表达与草稿入口 |
| 保存很快，后来找起来费劲 | 当初留下了什么线索，实际使用了什么称呼 | 名称候选、别名、整组说明与位置呈现 |
| 初次整理顺利，后来位置过时 | 哪次物品移动没有及时更新，当时怎样使用手机 | 详情的维护入口、批量移位与桌面入口 |
| 使用间隔较长，回来仍能找到 | 期间发生了几次实际寻找，记录帮助了哪些事情 | 保持已有内容与搜索路径稳定 |

首轮研究逐个记录“用户原本要做的事 → 采用的记录方式 → 实际输入 → 保存结果 → 后续寻找结果 → 维护行为”。用户愿意继续的证据包括主动记录下一件、在实际寻找时再次打开，以及物品变化后主动更新。当前这些结论的状态为待用户体验验证。
