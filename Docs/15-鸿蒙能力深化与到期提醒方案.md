# 鸿蒙能力深化与到期提醒方案

版本：1.1 · 调研日期：2026-11-01。本文解释能力选择及产品价值；接口合约由 `08` 维护，日期算法由 `09` 维护，账号准备见 `16`。目标为 HarmonyOS 7.0 / API 26，开发主体为个人。

## 1. 这次增强解决什么问题

用户已经决定录入物品时，应用帮助他少输入；用户有需要时，应用帮助他快速找到；日期到了，系统替他记住。这三个时刻构成本次能力选择的依据。方案评估同时计入理解、准备、录入和后续维护的成本。

| 当前任务 | 采用的能力 | 用户操作与收益 | 对应需求 |
| --- | --- | --- | --- |
| 录入有期限的物品 | 本地日期计算、系统提醒 | 填到期日或生产日期与保质期，保存后到期提醒 | F09 |
| 已拍下包装照片 | Core Vision 文字识别 | 选择照片中的日期填入，减少抄写 | F10 |
| 口述名称、说明或搜索词 | Core Speech 离线语音 | 说完确认文字，继续当前任务 | F18 |
| 查询或补记同款 | Scan Kit 默认扫码 | 查已有同码记录，复用已确认的名称 | F17 |
| 从桌面想起要查一下 | Form Kit、图标快捷方式 | 直接进入记录、搜索、日期或扫码 | F11 |
| 已在图库选好了照片 | Share Kit | 把当前选择送入记录，接着保存 | F11 |

扫码是否比输入名称更省事、语音是否减少修正时间，均通过真实任务观察确认。位置二维码已取得官方生成能力依据，产品侧将其作为长期储物场景的研究备选，待用户确有标签习惯时评估制作和维护成本。本版 F17 采用商品条码查找与同款复用。

## 2. 通用到期管理：录入一次，到期提醒

到期适用于所有物品，药品、化妆品、电池、食品等均使用相同表单。用户在录入时选择一种填法：

1. **到期日期**：直接填写日期。
2. **保质期**：填写生产日期与天、月或年数，应用即时算出到期日期。

例如生产日期为 2026-11-01、保质期为 6 个月，表单显示“到期日期：2027-05-01”。用户和物品一起保存，到期当天上午 09:00 提醒一次。同一天到期的物品合并成一条提醒。

日期是选填项。生产日期暂缺时，已输入的保质期随物品保存，表单提示“补上生产日期可计算到期日”；计算依据完整后安排提醒。填写过去日期时，记录进入应用内待关注列表。

用户侧只需要理解“到期提醒”。首次保存日期时提供一次开启入口，完成系统授权后，后续日期沿用设置。提醒里能进入物品详情，修改日期、调整数量或归档。完整算法见 `09`，页面见 P20、P21。

## 3. 系统通知怎样在应用退出后出现

普通通知负责展示消息，后台代理提醒负责把未来时刻交给系统。华为 Notification Kit 的说明区分了应用运行期间的本地通知和应用退出后的渠道；定时提醒由 Background Tasks Kit 承接。[通知概述](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/notification-overview)

新版代理提醒指南明确列出生活类“临期提醒”。已成功发布的提醒由系统计时，应用进程结束后仍能工作。手机接入需要在开发者平台申请代理提醒能力，审批通过后打开开关、重新生成 Profile，并声明 `ohos.permission.PUBLISH_AGENT_REMINDER`。API 26 每个应用最多持有 64 个有效提醒，已经弹出且仍未关闭的提醒也占用名额；较早 API 的上限为 30。[代理提醒指南](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/agent-powered-reminder)

**个人账号状态：待核验入口与审批结果。** 上述公开指南提供场景及申请方法，个人主体能否在当前账号完成开通，需要用实际个人账号查看入口并取得审批结论。本文将代理提醒列为有条件接入方案，交付以实际资格为依据。系统日历提供另一条已经有公开接口依据的安排路径，用户可直接使用。[日历事件开发指南](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/calendarmanager-event-developer)

| 接入条件 | 应用怎样承接 | 用户看到的结果 |
| --- | --- | --- |
| 代理提醒权益、签名和通知授权就绪 | 系统代理计时并发布普通通知 | “到期提醒已开启”及具体提醒日期 |
| 通过系统日历承接并取得授权 | 创建专属日历与每日汇总日程 | “通过系统日历提醒”及具体日期 |
| 用户保留当前权限 | 保存日期并提供应用内列表 | “日期已保存”，可点开启到期提醒 |
| 容量或接口条件需要处理 | 保留实际登记结果与待处理日期 | 具体待安排日期和解决入口 |

用户在录入时只处理日期信息。应用根据实际可用条件接入，在申请日历权限时说明用途；技术状态用于开发与问题处理。系统接口成功表示登记完成，真实横幅、锁屏和声音按用户系统设置呈现。

## 4. 一次提醒与同日汇总

每个日期版本对应一次提醒。日期当天当地 09:00 触发，同日合为一个任务。默认通知显示“我的家当 · 3 条日期提醒”，点击进入 P12 查看；详细内容由隐私设置控制。当天 09:00 之后补录或补录过去日期时，应用内列表立即呈现对应状态。

API 26 的代理提醒最多容纳 64 个有效任务。开发侧先查询系统实际有效列表，再逐个安排未来日期汇总并保存返回标识；剩余日期向用户提供日历承接。日期修改、处理、归档和回收均更新对应安排，同一汇总日使用一个外部承载方式。详细登记、取消、容量和重启核对规则由 `09` 维护。

到期当天显示“今天到期”，次日显示“已过期”。用户标记日期已处理只结束这次关注，物品状态仍由用户调整数量、归档等操作决定。记录持续有用，来自提醒帮他完成一次实际处理。

## 5. 实况窗与小艺能力的调研结论

实况窗适合订单或服务在一段时间内持续变化的状态。华为公开 FAQ 将推送实况窗的账号条件写为企业账号，并要求先开通推送服务；场景还需要满足实况窗准入与设计评审。包裹待取的系统表现属于这种服务接入结果。[实况窗场景与推送机制 FAQ](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-liveview-2?docScope=all)

意图框架可把业务分发到小艺对话、搜索和建议，其官方 FAQ 明确当前准入主体为企业开发者。[意图框架接入 FAQ](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-intents-kit-5)

本次个人版采用“普通系统通知 + 日期列表 + 桌面卡片 + 四个图标快捷方式”完成提醒与直达。后台代理提醒单独按个人账号的实际权益核验。原型展示普通通知的版式和点击去向，实况窗保留为本节资格研究结论。这样每项进入页面的能力都有对应的开发主体、接口和实施条件。

## 6. 扫码、语音和快捷方式的实际价值

Scan Kit 提供系统默认扫码界面、相册入口及二维码生成能力。默认界面使用系统预授权相机访问；API 26 可查询设备是否支持该界面。条码结果是码值，应用以本地同码记录帮助查重和复用信息；首次遇到某个条码时，用户补上名称或照片完成记录。二维码生成可供后续标签场景研究，当前交付采用应用内商品码查找。[默认界面扫码](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/scan-scanbarcode)、[生成码图](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/scan-generatearray?docScope=all)

Core Speech Kit 提供中文普通话离线识别，当前服务区域为中国大陆，设备模型及初始化结果决定可用性。用户点击语音后才申请麦克风；识别结果先放在可编辑候选区，用户确认后进入名称、说明或搜索词。现有位置名称可作为本地热词提高识别机会，实际质量以手机结果为准。[能力简介](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/core-speech-introduction)、[语音识别 API](https://developer.huawei.com/consumer/cn/doc/doccenter-references/api/hms-ai-speechrecognizer)

静态快捷方式在应用配置中定义，桌面最多展示四项。本版配置“记一件、找东西、看临期、扫一扫”，和卡片、应用内入口共用路由。[创建应用静态快捷方式](https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/typical-scenario-configuration)

这些能力采用官方服务并融入 HarmonyOS 体验。“鸿蒙专属接入”表示本产品采用该平台的系统接口；用户任务本身仍用拍照、输入、查找等熟悉动作表达。原型与页面继续使用 `06`、`07` 的绿色语义色、实底内容、系统操作层和连续转场。

## 7. 交付与验证状态

官方通知、代理提醒、扫码、语音、快捷方式指南及企业准入 FAQ 已完成文字调研。系统能力的正式实现按 H07、H11—H14 和 A25—A32 执行；个人代理提醒审批、真实通知送达、离线模型和扫码效果均待实际接入验证。

本轮原型承担两种日期填法、自动计算、到期提醒、通知示意、扫码结果和语音候选的交互演示。网页演示结果与原生能力结果分别记录，实际操作见 `Prototype/README.md`。
