# 我的家当：产品定义与使用场景

版本：1.1 产品设计基线 · 2026-11-01。关联：`02-低负担记录核心机制.md`、`03-产品需求规格.md`。

## 1. 产品是什么

“我的家当”是一款帮助个人记住自己有哪些物品、物品放在哪里以及当前状态的 HarmonyOS 7.0 应用。用户通过一张照片或一个名称留下记录，在寻找、购买、整理和使用物品时快速得到答案。

对用户的承诺是：**记住放哪，用好已有。**

产品名为“我的家当”，项目名为 ItemNest，包名为 `com.imotong.itemnest`。个人记录保存在设备上的应用空间，系统备份、换机和用户主动导出帮助用户长期保有这些记录。

## 2. 用户为什么会需要它

用户想到这类应用，通常发生在一个具体时刻：搬家时打开了一箱东西，准备出门却找不到充电器，购物时想不起家里还有多少电池，或者把工具借给朋友后忘记放在谁那里。产品应当在这些时刻接住用户的需要。

| 场景 | 用户此刻想完成的事 | 一次使用应提供的结果 |
| --- | --- | --- |
| 收起一件偶尔使用的物品 | 以后想用时能找到 | 一条包含外观和存放位置的记录 |
| 整理抽屉、柜子或搬家纸箱 | 先记住这一处装着什么 | 一组照片、可搜索的简短说明和位置 |
| 寻找物品 | 迅速缩小寻找范围 | 匹配的物品、照片、位置路径与当前状态 |
| 准备购买 | 确认自己是否已有，以及现有数量 | 清楚展示相关的在手、借出和历史记录 |
| 移动物品或借给别人 | 顺手更新变化 | 一次简短操作完成位置或状态更新 |
| 留意物品有效期、保修期或归还日期 | 在合适的时候想起来，并顺手处理 | 通用日期记录、计算预览，以及用户选择的系统提醒 |

这些场景是本轮产品设计的工作假设。用户已经确认的是产品主题、记录意愿的重要性、HarmonyOS 7.0 的体验方向和酷安参考偏好。使用频率、常见物品类型、整理习惯和方案效果通过后续真机体验研究获得证据。

## 3. 用户获得价值的过程

### 第一件物品就有价值

首次打开直接进入“家当”，提供“记下一件”和“看看示例”。引导文案为：“先记一件你以后会找的东西。”用户拍照或输入名称即可保存；选择位置后，保存回执直接呈现“充电器 · 书房 / 书桌抽屉”。

这条记录当天就可以用于寻找，随着记录积累，用户建立自己的物品记忆。

### 整理规模由用户决定

用户可以记一件充电器，也可以把一箱换季用品记为一组。单件记录和整组记录都属于完整、可用的记录。整组记录显示“整组”标识；数量统计分别展示记录条数与明确填写的单件数量。

### 价值在真实任务中反复出现

记录入口随时可达；搜索优先呈现名称、照片、位置和状态；详情页把“改位置”“借出 / 归还”“调整数量”放在容易操作的位置。记录和维护围绕真实物品发生的变化展开。

## 4. 版本 1.0 的完整体验

| 能力组 | 用户可完成的任务 |
| --- | --- |
| 记下 | 名称录入、系统拍照、相册选择、单件与整组记录、连续记录、图片文字候选、语音填写与同款复用 |
| 找到 | 名称与备注搜索、位置浏览、分类和状态筛选、常用物品快捷访问、商品条码查找 |
| 更新 | 编辑、批量移位、数量调整、借出和归还、归档、回收与恢复 |
| 留意 | 任意物品的到期日期或保质期计算；到期当天提醒一次，同日汇总 |
| 方便进入 | 桌面服务卡片、四个图标快捷方式、接收系统图片分享、保持任务上下文的返回路径 |
| 长期保有 | 本地记录、手动完整备份、清单导出、恢复预览、系统备份与换机接入 |
| 舒适使用 | HarmonyOS 原生组件与材质、明暗主题、系统字体与字号、屏幕朗读及单手操作 |

所有能力的详细边界以 `03-产品需求规格.md` 为准，实施分阶段完成，版本交付以整套核心任务能够连续完成为标准。

到期能力面向所有物品。药品、化妆品、电池和食品都能设置，用户还可以为自己的其他物品选择关注日期。系统提醒以个人开发者的实际权益、签名、用户授权和设备能力为接入条件，选择依据与准备事项见 `15`、`16`。

## 5. 信息与操作的优先级

用户最常需要回答四个问题：叫什么、长什么样、放在哪、现在是什么状态。首页、搜索结果和详情首屏优先呈现这些信息。分类、标签、数量和日期随任务逐步出现；用户在编辑时可以完整访问。

主导航为“家当”“位置”“我的”。“记下”是独立的主要操作，持续位于拇指容易触及的位置。“提醒”入口出现在“我的”和具有相关内容的首页摘要中。

首页以实际记录为主体。用户拥有零条、一条和大量记录时，页面分别提供明确的起点、可立即使用的记录和高效的查找方式。

## 6. 产品成功的判断

核心结果是：**用户在一次真实的物品问题中，通过已有记录完成了查找、确认或更新。**

评估时观察首次保存所需时间、找到指定物品所需时间、位置更新成本、记录与实物的一致程度，以及用户再次有需要时是否主动使用。用户间隔一段时间才打开应用，也可能得到很高的价值；持续使用按真实任务发生的周期理解。

首轮验证使用 5—8 位自愿体验者，每人从自己的物品中选择 3—5 件，再进行一次实际寻找和一次位置变化。该人数是形成问题线索的研究规模，结论适用于观察到的场景。通过录屏和简短访谈记录完成路径、犹豫点与自述原因，数值目标见 `02` 和 `13`。

## 7. 设计语言

本次设计语言定为“温和、清楚、随手可用”。家当照片提供生活感，暖白底色与深绿色强调色保持安定感；系统材质用于导航和操作层，内容卡片保持清楚的边界与阅读对比；动效帮助用户理解页面层级、操作结果和物品位置变化。

当前工作区提供的搬家人物图标用于应用身份、首次使用和轻量空状态。功能界面采用系统字体、系统符号和统一组件，具体规范见 `06`、`07`。

## 8. 首版交付条件

开发者应当能够从空数据开始，完成“记下一件 → 查到位置 → 移动物品 → 再次查找 → 备份并恢复”的全流程；整组记录、日期提醒、外部图片入口和可访问性分别有明确的验收步骤。产品文档、原生实现与真机结果共同构成版本交付依据。
