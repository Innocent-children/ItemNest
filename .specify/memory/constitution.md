# 我的家当（ItemNest）Constitution

## Core Principles

### I. 按指定需求创建新项目

这是一个新项目，应用名称为“我的家当”，项目名为 `ItemNest`，包名为 `com.imotong.itemnest`，均由用户指定。以用户提供的 `docs/` 需求和素材包为输入，从零创建工程及业务功能。需求编号、优先级和规则编号用于追溯输入，不代表业务实现已经完成。禁止查看 `2fe89c3c` 及之前的 Git 记录。

### II. 数据由用户掌握，外部改动必须确认

应用核心不要求账号，不申请网络权限，物品数据和端侧识别在本机处理，目的是保护用户数据。华为官方系统备份、换机等能力按产品需求正常接入，不把官方系统服务处理数据视为违背本地数据原则，也不因此增加确认门槛。系统入口按产品定义的隐私开关执行。新增或改动由用户在应用内确认；仅本应用互动卡片上的“用掉 1”可按 R34 直接执行并提供撤销。AI 不能擅自改库存、位置或日期。

### III. 数量、借还和撤销保持一致

数量使用百分之一单位的整数。业务写入读取最新数据并在事务内校验、排队执行；份合并必须维护借出的来源关系。撤销必须核对受影响对象的版本，拒绝覆盖后续改动。待办、搜索、卡片和通知共用业务计算，禁止在各入口另写一套数量规则。

### IV. 先找到，就地完成

搜索是首页的主要入口，“＋”在当前页面打开统一记下面板。日常操作完成后保留栏目、页面和滚动位置，能撤回的操作提供撤销。界面使用 `docs/product.md` 定义 的中文术语，不展示数据表名、枚举值和内部调度状态。系统材质与动效遵循 `docs/design.md`，同时支持深浅色、大字号、读屏和减少动画。

### V. 主动查证能力，按实际支持自动降级

工程师主动查询官方资料并核对 SDK，为当前范围内的能力决定实现方案。编译 SDK、最低运行版本、设备支持、模型状态、运行授权和用户偏好分别处理；依据接口实际支持检查，不用芯片档次或机型推定结论。支持时使用增强能力，不支持、未就绪或调用失败时保留输入并自动回到完整基础流程。搜索、手工记下、待办、数量与备份不依赖增强能力。具体策略见 `capability-compatibility.md`。

实际需要平台资格的能力在接入时核验，不把全部资格和真机结果作为工程开工条件。US10 不在当前实施或检查范围；高端硬件不使它自动启用。不得擅自增加服务器、网络权限或持续后台保活。

### VI. 交付结论必须有证据

需求必须能追溯到故事、任务和验收场景。实现后按 R1–R40、T1–T15 和能力清单进行适当验证；文档规划不能声称编译、安装、真机或平台验收已经通过。华为规范整改必须写清发现、证据、处理步骤和通过条件；无法静态判定的项目保留验证任务。

## 项目边界

- 目标为 HarmonyOS 原生应用，覆盖手机、平板和折叠屏；API 26 为编译与增强体验基线，不等于最低运行版本。T001 评估 HarmonyOS 6.0 / API 20 起的兼容方案并依据依赖、工具链和实际验证锁定最低版本；锁定前不宣称低版本已支持。
- `docs/` 六份文档保留为输入依据，通过需求映射和差异说明承接，不直接改写需求文档。
- 原 P0/P1/P2 按 `docs/request.md` 保留供追溯和排序。用户要求完整实施非企业范围，US1–US9 均纳入交付，不能自行延期 P1/P2。SYS-04/SYS-05、AI-09 模型生成部分、SYS-08 保留在文末 US10，本次不实施、不申请、不列入当前检查表；排除项不计为验证通过。65 条核心 P0 是最低要求，不能替代完整交付。
- 连续记下、购物、备份和本地查询先交付应用内完整流程；不因未选企业扩展而缺失功能。代理提醒和 SYS-06 端 A2A 单独核验资格，不自动归为企业专属；未选扩展不引入空声明、可启用开关或无法使用的引导。
- 应用名、包名和图标按用户指定直接使用；用户已确认图标合法，不另设权属或素材合规门槛，工程验证正确引用和设备显示即可。`vendor` 的真实发行者信息若无法从已有资料确定，只影响相应发行配置，不阻塞工程创建。
- 当前轮次只修订文档，不开发、构建、安装或开通平台。用户先前完整开发的目标保留，恢复实施以用户后续指令为准。

## 交付流程

规格、研究、契约、任务与验收保持一致。常规技术选择由工程师查证后决定，并记录依据；已确认事项不重复请求指示。文档质量、工程任务和运行验收分别记录，平台或设备验收留在相关实施阶段，未执行不作为整体开工阻塞。只有不可推导的身份信息、账号持有人必须执行的操作或产品/隐私范围变更才需提出具体问题；独立工作继续。应用任务仅在实际完成后勾选。

## Governance

用户最新指令优先于本文件。本文件是后续规格和实施的项目原则；变更时记录原因、影响文档和迁移安排。治理原则的兼容性破坏升主版本，新增约束升次版本，文字澄清升修订版本。每次规格或实现交付都核对上述原则，并保留尚未完成的验证项。
